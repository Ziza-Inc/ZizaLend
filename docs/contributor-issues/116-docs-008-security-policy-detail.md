## Context

`SECURITY.md` exists. A reportable-vulnerability policy is only useful if a researcher can tell what is in scope, what happens after they report, and how long they should expect to wait. Without that, reports go to the issue tracker, which is public.

## Task

- State what is in scope and what is not
- Give the response expectations and the disclosure timeline
- Say explicitly not to open a public issue, and where to send the report instead
- List the known, accepted limitations so they are not reported repeatedly

## Definition of Done

- The policy answers scope, process, and timeline
- A researcher can act on it without asking a question first
